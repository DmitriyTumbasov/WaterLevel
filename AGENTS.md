# AGENTS.md

Инструкции для кодинг-агента, работающего в этом репозитории.

Этот файл — договорённости, а не защита. Настоящие ограничения живут в правилах
ветки `main`, в правах доступа GitHub и в том, какие секреты агенту не выдаются.
Если инструкция здесь противоречит этим ограничениям, побеждают ограничения.

## Что за проект

Сервис на ASP.NET Core, который собирает уровень воды с внешнего источника
и показывает историю на графике.

- Раз в `Collector:IntervalMinutes` минут опрашивает `Collector:SourceUrl`.
- Из ответа берёт единственную станцию — `Collector:StationId` (по умолчанию `76556`, Киров).
- Сохраняет запись, только если момент наблюдения новее последнего сохранённого.
- Отдаёт историю и последнее значение через HTTP API, рисует график статической страницей.

## Структура

```
WaterLevel.sln
├── WaterLevel.Web/              приложение (Microsoft.NET.Sdk.Web, net8.0)
│   ├── Program.cs               точка входа, регистрация DI, три эндпоинта
│   ├── Models/                  SourceWaterLevelRecord (форма ответа источника),
│   │                            WaterLevelMeasurement, WaterLevelHistoryPoint
│   ├── Options/                 CollectorOptions — секция конфигурации Collector
│   ├── Services/
│   │   ├── WaterLevelApiClient.cs        HTTP к источнику + разбор записи
│   │   ├── WaterLevelCollectorService.cs BackgroundService, периодический сбор
│   │   └── WaterLevelRepository.cs       весь SQL к PostgreSQL (Npgsql, без ORM)
│   ├── wwwroot/index.html       страница с графиком
│   └── Dockerfile               контекст сборки — сам каталог WaterLevel.Web
└── WaterLevel.Tests/            xUnit, модульные тесты
```

### Поток данных

```
источник (HTTP JSON)
   → WaterLevelApiClient.GetStationRecordAsync   выбирает нужную станцию
   → WaterLevelApiClient.ParseMeasurement        строит момент наблюдения из dt + tm
   → WaterLevelRepository.InsertIfNewerAsync     пишет, если новее последнего
   → PostgreSQL, таблица water_level_measurements
```

Схема таблицы создаётся кодом при старте: `EnsureDatabaseAsync` в `Program.cs`.
Отдельных миграций нет. Из этого следует, что **приложение не стартует без
доступной базы** — учитывайте при smoke-тестах.

### Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Живость сервиса и доступность базы. `200` — норма, `503` — база недоступна |
| GET | `/api/water-level/latest` | Последнее измерение, `404` если записей нет |
| GET | `/api/water-level/history?from=&to=` | История точек, обе границы необязательны |
| POST | `/api/water-level/collect` | Немедленный опрос источника: `{ "inserted": bool }`, либо `502`, если источник недоступен |

## Команды

Перед открытием PR прогоните все четыре и добейтесь зелёного результата.
Это ровно то, что выполняет CI, — расхождений быть не должно.

```bash
dotnet restore WaterLevel.sln --locked-mode
dotnet format WaterLevel.sln --verify-no-changes --no-restore
dotnet build WaterLevel.sln -c Release --no-restore -warnaserror
dotnet test WaterLevel.sln -c Release --no-build
```

Починить форматирование, если третья команда ругается:

```bash
dotnet format WaterLevel.sln
```

Запуск локально — поднимает приложение и PostgreSQL:

```bash
docker compose up --build
```

Приложение будет на `http://localhost:8080`.

## Правила работы

**Ветки и PR**

- Прямой push в `main` запрещён и технически заблокирован. Работайте в ветке,
  открывайте PR.
- Имя ветки: `feat/…`, `fix/…`, `test/…`, `chore/…`, `docs/…`.
- Один PR — одна задача. Мелкий PR ревьюится за минуты, большой копится днями.
- Слияние выполняет человек. Не пытайтесь слить свой PR сами.

**Качество**

- Сборка идёт с `-warnaserror`. Сейчас предупреждений ноль, и это состояние нужно
  удерживать: новое предупреждение уронит CI.
- Не отключайте анализаторы и не глушите предупреждения директивами, чтобы
  «сделать зелёным». Чините причину.
- `Nullable` включён. Не ставьте `!` там, где значение реально может быть null.

**Тесты**

- Тесты не ходят в сеть и не поднимают базу. HTTP подменяется через
  `HttpMessageHandler` — пример в `GetStationRecordTests.cs`.
- Тест должен падать, если сломать проверяемую логику. Тест, который проходит
  при любой реализации, бесполезен.
- Не закрепляйте в тесте поведение, в правильности которого не уверены.
  Лучше не покрыть, чем зацементировать ошибку.
- Логика `InsertIfNewerAsync` сейчас не покрыта: она требует живой PostgreSQL.
  Это известный пробел, а не недосмотр.

**Зависимости**

- Добавили пакет — обновите lock-файл и закоммитьте его, иначе CI упадёт на
  `--locked-mode`:

  ```bash
  dotnet restore WaterLevel.sln
  ```

- Версия SDK зафиксирована в `global.json`. Не меняйте её мимоходом.
- Новые зависимости обосновывайте в описании PR. Одна задача — не повод тянуть
  фреймворк.

**Что не коммитить**

- `bin/`, `obj/` — закрыты `.gitignore`, они уже один раз попадали в историю.
- Любые реальные пароли, токены, строки подключения к рабочим базам.
  Значения в `appsettings.json` и `docker-compose.yml` — локальные заглушки;
  не подставляйте на их место настоящие.

## Деплой

Схема: коммит в `main` → `Release` публикует образ в `ghcr.io/dmitriytumbasov/waterlevel`
с тегом по SHA → `Deploy staging` выкатывает этот тег на сервер и проверяет `/health`.

Прод выкатывается только вручную: `Deploy production` с обязательным одобрением
человека. Автоматического выката на прод нет и не должно появиться.

| Окружение | Порт | Проект compose | Опрос источника | Откат |
|---|---|---|---|---|
| staging | 8081 | `waterlevel-staging` | раз в 6 часов | вручную |
| production | 8080 | `waterlevel-production` | раз в час | автоматический |

- Выкатывается **только тег по SHA**. Тег `latest` подвижный, откатиться на него нельзя.
- На проде неудачный smoke-тест возвращает предыдущий образ автоматически.
  Выкат при этом всё равно считается неуспешным — откат не маскирует проблему,
  а лишь не оставляет сервис лежать.
- Ручной откат — запуск workflow с прошлым SHA-тегом. Собирать ничего не нужно:
  образ уже в реестре.
- Файлы выката лежат в `deploy/`. Корневой `docker-compose.yml` — только для локального
  запуска, на сервере он не используется.
- Сервер не собирает образ и не хранит исходный код. Он умеет ровно две вещи:
  забрать образ из реестра и перезапустить контейнеры.
- Пароль базы приходит на сервер файлом `.env`, а не аргументом команды.
  Не переносите секреты в командную строку: аргументы видны в списке процессов.

## Границы

Агент не получает и не запрашивает:

- продовые секреты и строки подключения;
- доступ к продовой базе данных;
- административные права в репозитории;
- право слияния PR и выпуска релиза.

Если задача выглядит так, будто требует чего-то из этого списка, — остановитесь
и опишите, что именно понадобилось. Не ищите обход.

## Известные особенности

Это не задачи «на сейчас», а контекст, чтобы не принять их за новые поломки.

- `ParseMeasurement` читает уровень через `InvariantCulture`. Если источник
  пришлёт `"123,45"` с запятой, запятая будет понята как разделитель тысяч
  и получится `12345`. Формат источника не проверен.
- Поле `tm` источника содержит перечень сроков наблюдения через запятую.
  Берётся последний.
- `POST /api/water-level/collect` открыт без аутентификации.
- Миграций нет, схема создаётся при старте. Изменение схемы — правка
  `EnsureDatabaseAsync`, и оно должно быть совместимо с уже существующей таблицей.
